# 1.2.23-beta

The candied water bottle, from the actual cause this time.

Two facts were in the way, and both are in AoA's data rather than in anything guessable from vanilla's
behaviour:

**AoA puts its candied water in the `minecraft:water` fluid tag.** So vanilla's glass bottle sees it as
water and does exactly what it does with water: it takes the source and hands back a *water bottle*. Any
add-on that wants to bottle candied water has to act before vanilla's bottle does, and cannot rely on
the "not water" case being free.

**A click on a fluid surface is an item use, not a block use.** The client's own block hit does not
include fluids, so the click never takes the block path and `RightClickBlock` does not fire at all -
which is why the previous handler, however correct it looked, never ran. The event that fires is
`RightClickItem`. Both are handled now, since a click that lands on a block takes the other path.

While here: the bottle is filled into the hand that actually holds it. The previous code asked the
player which hand they were "using", which is the main hand whenever they are not using anything.

The build now refuses a `Bottles` that does not mention both click paths, and refuses definitions of
the two handlers that are never registered with the bus - a forgotten registration line compiles
perfectly and leaves a handler that never runs. Both were checked by breaking them and watching the
build fail.
