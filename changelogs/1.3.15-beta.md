# 1.3.15-beta

A build audit that the jar ships nothing of AoA's.

The add-on's whole licensing story is that AoA draws its own art: this jar reaches AoA by registry name and
by texture path, and the textures it carries are either generated from vanilla's shapes or drawn by hand.
That is easy to break by accident - copying a soil texture to "tint" it is the obvious way - and nothing
would have noticed, because a copied file is usually renamed.

The build now hashes every PNG in the jar against every PNG in the AoA jar and refuses to package if any
is byte for byte the same. Tried by copying AoA's `aromatic_dirt.png` into the assets: the build stopped
and named the file. Current status: none of the 158 textures in the jar matches any of AoA's 3380.
