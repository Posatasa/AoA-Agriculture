# 1.2.28-beta

The creative tab has a fixed order now.

It was showing items in registry order, which is whatever order the item registers happened to run
in - so the candied water bottle landed in the middle of the buckets, and the metals were in the order
they had been added to the code rather than an order anyone chose.

The tab now lists, in this order:

1. the farmland blocks, unchanged: each soil's farmland and its fertilised counterpart;
2. the buckets, metal by metal: **Limonite, Rosite, Emberstone, Blazium, Lunar, Shyre, Dark**, and
   within a metal in the buckets' own order - empty, water, lava, candied water;
3. the candied water bottle, after the buckets rather than inside them.

Anything that names this tab and is not on those lists is still added at the end, so a future item
cannot go missing by being left off a list. The build checks that the tab keeps overriding its item
list and keeps calling both adders; losing either leaves a tab missing items with no error anywhere.

Also fixed the reference checker: it treated a member inherited from a JDK supertype (such as
`NonNullList#add`, which comes from `ArrayList`) as unresolvable. Those are out of scope, like every
other library member, and are no longer reported.
